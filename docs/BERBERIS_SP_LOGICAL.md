This candidate follows the deployed conditions/direct-ADD-source optimization.
It is motivated by the complete 金铲铲之战 loading capture on 2026-09-08:

## Implementation

- SP now participates in source-aware selection for the existing seven GPR
  cache slots, competing with X0–X30. No extra host registers are reserved.
  Usage index 31 explicitly means SP; XZR/WZR reads and discarded writes
  continue to bypass cache accounting and lookup.
- The region prologue loads a selected SP from its dedicated ThreadState
  offset. SP writes immediately update ThreadState, then its cache entry,
  just like existing GPR writes. Entries reload when entering a region;
  no cross-region cache contract or deferred writeback is introduced.
- Unsigned-offset, indexed and integer pair memory operations form addresses
  directly from read-only cached base registers. TBI still changes only a
  temporary effective address, and pre/post-index architectural writeback
  remains after successful memory access. Recovery points are retained.
- Zero-shift, non-inverted 64-bit AND/ORR/EOR use cached or zero source registers
  directly. Inverted operations, flag-setting operations and 32-bit operations
  retain the existing scratch-register path.

The first candidate passed all 175 correctness tests, but the new stack-writeback
benchmark grew from 3368 to 3500 host bytes (+3.92%), exceeding the 3% size gate.
Address formation was then combined to remove redundant base copies. The final
stack-writeback region is 3308 bytes, below the original baseline. Initial logs
are retained in `candidate-run/`; final results are separate.

## Correctness coverage

The final device suite passed **175/175** tests. The four new tests cover:

- SP arithmetic, WSP truncation, logical-immediate SP destinations, and SP versus
  zero-register interpretation, comparing every sequence prefix with the interpreter;
- tagged and untagged stack memory, integer pairs, scalar and SIMD pre/post-index
  writes, discarded zero-register loads/stores, and recovery-map presence;
- SP write-through at a pending-signal backedge exit and reloading modified SP
  on subsequent entry, including execution through local backedges;
- 4096 cached/uncached logical regions spanning both widths, all four logical
  operation codes, all zero-shift kinds, and source/destination/zero aliases.

Existing memory, signal polling, register cache, SIMD, JNI and runtime tests also
passed. No assembler encoding changed in this batch.

## Performance and build validation

Both binaries use the same eleven-scenario benchmark source, built against their
respective translators. Initial validation used 20,000,000 iterations per scenario,
three alternating adjacent A/B pairs, on logical CPU 0. Game threads were temporarily
restricted to CPUs 2–7 to exclude both SMT threads of the benchmark core.

The first three-pair comparison failed the unchanged `condition_select` control
at +3.30%, with substantial between-run variation and essentially unchanged
retired instruction counts. Ten additional pairs for that control were specified
before collecting them. All thirteen pairs are retained and pooled: median
0.8859 → 0.8841 ns/guest (-0.20%), mean 0.89843 → 0.89102 ns/guest (-0.82%).
No original sample was removed. Other scenarios retain their original three pairs.

unknown), which also limits direct percentage comparisons.
